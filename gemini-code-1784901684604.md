# Blueprint de Arquitectura Web: Asadero Kikos

## 1. Resumen Ejecutivo y Objetivos de Negocio
*   **Propósito:** Desarrollo de una plataforma web transaccional e informativa para "Asadero Kikos". Permitirá la visualización dinámica del menú, geolocalización del local, conocimiento de la marca y la gestión de pedidos mediante un carrito de compras interactivo que culmina en WhatsApp.
*   **Público Objetivo:** Clientes finales (B2C) en la zona de cobertura del restaurante que buscan realizar pedidos a domicilio o para recoger, utilizando una interfaz rápida y móvil.
*   **Objetivos B2B/Conversión:** 
    *   Centralizar y simplificar la actualización del menú a través de Google Sheets, eliminando la dependencia técnica del dueño.
    *   Aumentar la tasa de conversión automatizando la captura estructurada de pedidos hacia el WhatsApp del negocio.
    *   Generar trazabilidad operativa construyendo un registro histórico de intenciones de compra (pedidos generados) para análisis de inteligencia de negocios (BI).

## 2. Pila Tecnológica (Tech Stack)
*   **Frontend:** HTML5, CSS3, Vanilla JavaScript. Enfoque "Mobile-First" para asegurar rendimiento en dispositivos móviles.
*   **Backend:** Node.js (con Express). Actuará como middleware para gestionar las peticiones a la base de datos, servir los archivos estáticos y manejar la lógica de negocio de forma segura.
*   **Automatización e Integraciones (Google Workspace):**
    *   **Base de Datos (Lectura/Escritura):** Google Sheets. Se utilizarán dos pestañas principales: `DB_Menu` y `Log_Pedidos`.
    *   **Capa de API:** Google Apps Script (desplegado como Web App). Actuará como puente seguro (endpoint) entre el backend de Node.js y Google Sheets para recibir y enviar datos en formato JSON.
    *   **Inteligencia de Negocios:** Looker Studio. Conectado directamente a la hoja `Log_Pedidos` para visualizar productos más vendidos, horas pico y volumen de transacciones.

## 3. Arquitectura de Datos
*   **Entidades Principales:**
    *   *Producto:* ID, Nombre, Descripción, Precio, Categoría, URL_Imagen, Estado (Disponible/Agotado).
    *   *Pedido (Log):* ID_Pedido, Fecha_Hora, Total, Productos_Detalle, Estado_Envio (Redirigido a WA).
*   **Flujo de la Información:**
    1.  *Actualización de Menú:* El dueño edita la pestaña `DB_Menu` en Sheets.
    2.  *Renderizado:* Node.js consulta el Web App de Apps Script, obtiene el JSON del menú, lo guarda en caché temporal y lo envía al Frontend para renderizar.
    3.  *Transacción:* El usuario arma el carrito y presiona "Pedir por WhatsApp".
    4.  *Trazabilidad:* El Frontend envía la data del carrito a Node.js. Node.js dispara un POST al Apps Script para registrar el pedido en `Log_Pedidos`.
    5.  *Conversión:* Simultáneamente, el Frontend genera el enlace `wa.me` con el mensaje pre-formateado y redirige al usuario.

## 4. Mapa del Sitio y Navegación (Sitemap)
*   **/** (Página Principal / Landing Page):
    *   *Sección Hero:* Propuesta de valor, imágenes destacadas del restaurante.
    *   *Sección Menú:* Grid dinámico de productos clasificados por categorías con botones de "Añadir al carrito".
    *   *Sección Nosotros:* Breve historia de Asadero Kikos y fotos del local.
    *   *Sección Ubicación:* Mapa embebido (Google Maps) y horarios de atención.
*   **Widget Flotante (Carrito):** Modal lateral o inferior accesible desde cualquier punto de la página que muestra el resumen del pedido, subtotal y botón de pago/redirección.

## 5. Historias de Usuario (Funcionalidades Core)
*   **Como** cliente, **quiero** navegar por un menú categorizado y con fotografías **para** elegir fácilmente qué deseo comer.
    *   *Criterios de aceptación:* El menú debe cargarse dinámicamente desde el backend; los productos marcados como "Agotados" en Sheets no deben mostrar el botón de compra o deben ocultarse.
*   **Como** cliente, **quiero** agregar productos a un carrito, ver el total y enviar el pedido a WhatsApp **para** finalizar mi compra sin fricciones.
    *   *Criterios de aceptación:* El sistema debe calcular correctamente el total y generar un texto limpio con saltos de línea (URL encoded) para la API de WhatsApp.
*   **Como** administrador (dueño), **quiero** cambiar un precio o añadir un plato en un Google Sheet **para** que se actualice en la página web sin tocar código.
    *   *Criterios de aceptación:* Los cambios en Sheets deben reflejarse en la web (considerando un tiempo de expiración de caché razonable en Node.js, ej. 5-10 minutos, para optimizar cuotas de lectura).
*   **Como** administrador (dueño), **quiero** tener un registro automático de los pedidos que se intentan hacer **para** revisar mi panel en Looker Studio.
    *   *Criterios de aceptación:* Cada clic en "Enviar a WhatsApp" debe insertar una nueva fila con fecha, hora y detalle en la hoja `Log_Pedidos`.

## 6. Requerimientos de Interfaz (UI/UX) y Componentes
*   **Tarjetas de Producto (Cards):** Diseño limpio con imagen, título, precio, descripción corta y controles de cantidad (+ / -).
*   **Notificaciones (Toast):** Alertas visuales no intrusivas cuando se añade o elimina un producto del carrito.
*   **Offcanvas / Modal de Carrito:** Un panel deslizable que resume los ítems, permite modificar cantidades, muestra el precio total y contiene el "Call to Action" principal hacia WhatsApp.
*   **Sección de Contacto Optimizada:** Integración limpia del iframe de Google Maps y enlaces directos a redes sociales.

## 7. Instrucciones Especiales para el Prompting (Agente de Código)
*   **Gestión de Caché en Node.js:** Es mandatorio implementar un sistema de caché en memoria (ej. variable global con timestamp) en el backend de Node.js para las lecturas del menú. Esto evitará agotar la cuota de ejecuciones diarias gratuitas de Google Apps Script ante picos de tráfico.
*   **Modularidad de JavaScript (Frontend):** Separar la lógica del carrito de compras en un archivo `cart.js` independiente, utilizando `localStorage` para persistir el carrito si el usuario recarga la página accidentalmente.
*   **Seguridad y CORS:** Configurar el Web App de Google Apps Script para aceptar solicitudes POST/GET únicamente desde el dominio/IP donde se alojará el servidor de Node.js.
*   **Manejo de Errores Silenciosos:** Si el registro en `Log_Pedidos` falla por alguna razón de latencia, el frontend *no* debe bloquear la redirección a WhatsApp; la venta es prioridad sobre el log analítico.
